# iperf3 本地与 VPS 测速

在 **Linux VPS 的 SSH 终端**启动本工具，选择端口和测试计划，然后在自己的设备上执行屏幕显示的 iperf3 命令。支持单连接、自定义连接数、依次 1 / 4 / 8 连接，以及上传、下载、双向测试。这里的“线程数”指并行 TCP 连接数。

VPS 负责逐轮监听和校验结果。本地不需要开放入站端口、不需要配置 SSH 密钥。第一版每轮需要执行一条本地命令；选择批量模式会自动安排下一轮，但本地仍需等待 VPS 的下一条提示。

## 运行

VPS 需要 Python 3.8+、iperf3，以及可读取自身进程信息的 `/proc`。所有 Python 功能使用标准库，无需 pip。高位端口测速本身不需要 root。

启动测速时自动检测 iperf3，缺失则根据 `/etc/os-release` 和可用包管理器安装：Debian/Ubuntu 使用 apt-get，RHEL/Fedora 使用 dnf（旧系统使用 yum），另支持 openSUSE 的 zypper、Alpine 的 apk 和 Arch 的 pacman。已经安装的依赖会跳过；安装成功后直接继续，无需重新运行。

依赖安装需要 root 或 sudo 权限，普通用户运行时会自动调用 sudo（可能需要输入密码）。Debian/Ubuntu 会刷新软件包索引，并自动选择不启动 iperf3 常驻服务。本工具不管理已有 iperf3 服务；软件源不可用或不提供所需包时会明确报错，请修复软件源后重试。

仓库的 `bash iperf3-tool.sh` 入口还会自动检测并安装 Python 3.8+。独立 Python 命令和工具箱统一安装器需要系统预先提供 Python 3.8+；老系统的软件源若仅提供更早版本，Shell 入口会提示升级。

从仓库运行：

```bash
cd iperf3_tool
bash iperf3-tool.sh
```

也可以安装成独立命令（在本目录执行）：

```bash
sudo install -m 0755 iperf3_tool.py /usr/local/bin/iperfprobe
iperfprobe
```

通过工具箱的统一安装器安装后：

```bash
vpstools
# 选择 9：iperf3 本地与 VPS 测速

# 或直接进入独立工具
vpstools run iperf
iperfprobe
```

本地设备也需要 iperf3。macOS 可以使用 `brew install iperf3`；Linux 使用发行版包管理器；Windows 使用兼容的 iperf3 客户端，在 PowerShell 中执行 VPS 显示的命令（如需可将 `iperf3` 替换为 `./iperf3.exe`）。Windows 客户端不保证提供重传及 RTT 字段。

## 交互流程

1. 填写本地可访问的 VPS IP 或域名。SSH 自动提示的地址可能是 NAT 内网地址，需要核实。
2. 选择随机未占用 TCP 端口，或输入自定义端口。随机范围为 20000～59999；自定义范围为 1024～65535。已有绑定的端口会拒绝使用，不会强杀其他进程。
3. 选择单连接、自定义 1～128 连接，或批量 1 / 4 / 8 连接。
4. 选择下载（VPS → 本地）、上传（本地 → VPS）或双向。
5. 设置测量时间、预热时间、重复次数、等待预算；默认 15 秒、2 秒、1 次、300 秒。
6. VPS 确认本次 iperf3 进程已监听后，显示一条本地命令。
7. 放行对应的主机防火墙和云安全组 **TCP** 端口，建议限制本地公网 IP；然后在本地执行命令。
8. 等待 VPS 显示结果及下一条命令；每轮依次执行，不要并发启动。
9. 完成后查看汇总；本次测速进程自动退出。

例如下载的本地命令：

```bash
iperf3 -4 -c 203.0.113.10 -p 43827 -P 4 -t 15 -O 2 -i 1 -R
```

请使用屏幕显示的实际地址、端口与参数。上传命令没有 `-R`。客户端决定并行连接数，VPS 会验证实际连接数、方向、测量时间和预热时间。执行错误参数不会被计入成功结果；交互模式允许重试（最多三次）、跳过或结束。

每轮使用 `iperf3 -s -1 -J`，会话完成后关闭该轮监听，再启动下一轮。自动恢复握手失败或扫描造成的不完整连接最多五次，且不刷新本轮时间预算；完整汇总校验失败不会被当作扫描无限重试。两轮间有短暂的未监听时间，请等待 VPS 的“监听就绪”。

## 命令行模式

```bash
# 随机端口，依次 1 / 4 / 8 连接下载
iperfprobe --host 203.0.113.10

# 固定端口，双向，每项重复三次
iperfprobe --host 203.0.113.10 --port 5201 --streams 1,4,8 \
  --direction both --duration 15 --omit 2 --repeat 3

# 单连接上传
iperfprobe --host 203.0.113.10 --streams 1 --direction upload

# IPv6；域名可通过 --family 6 显式选择 IPv6
iperfprobe --host 2001:db8::1 --streams 1,4,8

# 指定 VPS 本地监听 IP 和结果目录
iperfprobe --host example.com --family 4 --bind 192.0.2.10 \
  --output-dir /var/lib/iperf3-probe

iperfprobe --help
iperfprobe --version
```

命令行模式遇到失败直接结束，不询问重试；也仍需本地配合执行客户端命令。`--bind` 必须是 VPS 已配置的本地地址。退出码：`0` 全部成功；`1` 失败或跳过；`130` 用户中断、交互输入 EOF 或退出信号。

## 输出与清理

每次会话独立保存于 `~/.local/state/iperf3-tool/<UTC时间>-<随机编号>/`，会话目录权限为 `0700`。包括：

- `session.json`：版本、配置和完整测试计划。
- `report.json` / `report.csv`：逐轮状态、吞吐、指标及错误。
- `test-*.json`：iperf3 原始结果；每次连接都有独立文件。
- `*.err` / `*.guardian.err` / `*.validation.log`：错误与校验诊断。
- `*.state.json`：对应服务端 PID、就绪状态和退出原因。

汇总显示每项中位数，以及多连接相对单连接的吞吐倍数。接收端实测吞吐优先；部分版本的下载服务端只有发送端汇总，会明确标记“发送端”，不会把零占位接收记录当作实测速度。缺失的重传和 RTT 显示 `NA`，不是零。波动 CV 基于 VPS 端非预热区间；TCP 重传次数不等于实际丢包率。

完成、失败、等待超时、`Ctrl+C`、`TERM`、`HUP` 都会关闭本次监听。独立守护进程通过控制管道检测主进程退出，即使主进程被 `kill -9`，也会回收本次 iperf3 子进程。每轮最大生存时间为等待预算 + 测量时间 + 预热时间 + 15 秒；异常或恶意客户端不能让它无限运行。若连同守护进程也被强杀，或系统整体异常，则无法保证执行清理。

工具只操作自身创建的进程组，不按端口清除其他服务，也不修改 TCP/BBR 参数、防火墙或开机服务。已有防火墙与云安全组放行规则需要自己撤销；端口没有监听不等于规则被删除。输出文件在退出后保留，便于比较与排查，按需删除。

测速会尽量跑满带宽。六项测试各重复三次、每次测量 15 秒，在持续 1 Gbps 时仅测量阶段约产生 34 GB 流量，预热还会增加流量。

## 验证

```bash
bash -n iperf3-tool.sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

测试不安装依赖、不修改系统配置。依赖安装测试模拟发行版、权限及包管理器，覆盖安装跳过、自动安装、服务选项和失败处理。另覆盖双向 JSON、参数不符、零占位结果、占用端口、报告保留，并在已安装 iperf3 时执行限速回环测试：1 / 4 / 8 连接的六种组合、监听释放、错误连接数、控制管道断开、最大生存时间和主进程强制退出清理。没有 iperf3 时真实测试明确跳过。macOS 开发回环测试另需 lsof；正式入口限制为 Linux VPS。
