# SSH 密钥登录工具方案

日期：2026-10-09；更新：2026-10-10。第一版已实现；本文保留设计背景，实际接口和限制以 [使用指南](../ssh-key/README.md) 为准，验证结果见 [验收记录](ssh-key-acceptance.md)。

## 适合当前使用方式的选择

在现有 `vpstools` 中新增“SSH 密钥登录管理”，同时提供独立命令 `sshkeytool`。默认管理 root，也可选择已有的普通用户。第一版面向 Debian/Ubuntu、OpenSSH 和 systemd；根据用户后续指定，安装及修改测试仅在 `stone-hk` 完成。

日常在 VPS 上运行中文菜单；新连接验证在本地电脑的 OpenSSH 或 FinalShell 中完成。已有密钥继续使用，新密钥支持本地生成和 VPS 生成两种方式。本地生成时私钥留在电脑；VPS 生成时先临时保存私钥供下载，验证本地副本能够登录后清理服务器上的临时私钥。

第一版只管理指定用户。所有用户一起禁用密码、批量操作多台 VPS，以及可选的本地自动控制程序放在后续版本。

## 已确认的机器情况

以下来自本次讨论中的只读检查，不作为今后运行工具时的固定判断依据。

| 项目 | `taipei101-lax1` 的结果 |
| --- | --- |
| 服务器主机名、系统 | LAX1、Debian 13 |
| 管理用户、SSH 端口 | root、21919 |
| 主配置里的公钥选项 | `#PubkeyAuthentication yes` |
| 解析后的公钥认证 | `yes` |
| root 登录策略 | `prohibit-password`，解析输出使用别名 `without-password` |
| 全局密码认证 | `yes`，root 另外受禁止密码的策略限制 |
| 键盘交互认证 | `no` |
| 授权公钥文件 | 存在，1 条非注释记录，权限 0600 |
| 新连接测试 | 禁用客户端密码回退后，公钥认证成功 |

新工具必须识别系统默认值和已有设置。若当前状态满足所选策略，显示“已符合，无需切换”，不为改变菜单显示而重复生成密钥或修改注释。

## 菜单

```text
SSH 密钥登录管理

目标用户：root
公钥认证：已允许（系统默认）
授权公钥：1 把
密码认证：已禁止（root 登录策略）
新连接验证：尚未由本工具登记

1. 查看状态与判断依据
2. 添加公钥
3. 切换为仅密钥登录
4. 查看 / 删除公钥
5. 恢复本次修改前的登录配置
6. 备份与操作记录
7. 切换目标用户
8. 自动生成新密钥对
0. 返回
```

顶部显示实际状态，不使用一个“密钥模式已开启”概括所有检查。“配置允许”“当前连接已验证”“某把新公钥已经验证”分别展示。

添加公钥提供粘贴、公钥文件、GitHub 用户名和 HTTPS URL 四种来源。远程来源先显示获取到的公钥及指纹，选定后再添加；不会把一次导入变成持续信任远程地址的同步任务。

## 状态检测

1. 找到实际 SSH 服务、监听端口、配置文件和启动参数。遇到无法确定的自定义启动方式，给出检测结果，停止自动修改。
2. 使用 `sshd -T` 解析磁盘配置与默认值；针对选定用户、当前来源地址及服务器地址/端口使用 `-C`，使适用的 `Match` 规则参与判断。
3. 单独判断该用户是否允许公钥认证、是否允许密码或键盘交互，以及 `AuthenticationMethods` 是否要求额外认证。
4. 读取该用户真实的家目录和解析后的 `AuthorizedKeysFile`。不固定使用当前执行者的 `$HOME` 或 `/root/.ssh/authorized_keys`。
5. 展示授权公钥类型、指纹、备注和权限，并指出公钥上的来源或命令限制。文件存在和公钥数量不等于登录已成功。
6. 把解析结果标注为“当前磁盘配置”；把重载结果和实际新连接结果另行登记，避免将尚未加载的配置说成正在运行的状态。

来源地址相关的结果标注适用范围。不能因为当前管理 IP 能登录，就宣称所有来源都能登录。配置或公钥改变后，旧验证记录标记为需要重新验证。

遇到 SSH 证书、外部 `AuthorizedKeysCommand`、复杂多因素认证或第一版不支持的密钥路径时，仍可显示检测信息，但不自动重写其认证策略。

依据：[OpenSSH 配置解析与 Match](https://man.openbsd.org/sshd_config)、[sshd 的配置测试模式](https://man.openbsd.org/sshd)。

## 密钥管理

- 复用现有 RSA、Ed25519 等 OpenSSH 支持的公钥。新增密钥支持自动生成，默认 Ed25519，兼容性需要时可选 RSA。
- 使用 OpenSSH 解析和校验公钥，而不是只判断文本是否以 `ssh-` 开头。支持正常的多行公钥文件。
- 以公钥内容和指纹识别同一把密钥。已有同指纹记录带有限制选项时，保留原记录并显示差异，不能追加一条无限制版本来“去重”。
- 默认只追加选定公钥，保留其他公钥、注释和限制参数。通过原子写入保存文件，并保持正确属主与权限。
- 显示 `.ssh` 和授权文件的权限问题，修复只覆盖明确需要的目录与文件，不递归修改用户整个家目录。
- 删除公钥也需要备份；仅密钥模式下不允许直接删除最后一把文件授权公钥。更换或撤销可能影响管理登录的密钥时，验证另一把保留密钥的新连接后再提交。
- 本地生成的私钥留在电脑。VPS 生成的私钥只保存在权限受限的独立临时导出目录，不进入工具日志、配置备份或操作记录，也不默认打印到终端。授权文件查看以指纹列表为默认入口，可按需显示完整公钥。

依据：[授权公钥文件格式与权限](https://man.openbsd.org/sshd)、[ssh-keygen](https://man.openbsd.org/ssh-keygen)。

## 自动生成密钥对

菜单第 8 项提供两种方式，均同时生成公钥和私钥。生成操作本身不会关闭现有登录方式，也不会替换原有密钥。

| 方式 | 适用场景 | 私钥处理 |
| --- | --- | --- |
| 在电脑上生成 | 有现成本地 OpenSSH，希望私钥始终留在电脑 | 第一版提供完整生成命令，随后导入 `.pub`；后续本地辅助程序可自动执行 |
| 在 VPS 上生成 | 希望像参考工具箱一样，从服务器菜单直接生成 | 调用 `ssh-keygen`，公钥按需追加，私钥经已有 SSH/SFTP 连接下载到电脑 |

VPS 生成是第一版的完整功能，不依赖后续本地辅助程序。默认使用 Ed25519，也提供 RSA 选项；需要传统客户端格式时，可为 RSA 提供 PEM 私钥导出。是否加密私钥由用户选择，推荐设置私钥口令；口令通过交互输入，不写入命令行、日志或状态文件。

每次生成使用独立操作编号与文件名，防止覆盖已有私钥。临时导出目录位于 `/var/lib/sshkeytool/pending-keys/<操作编号>/`，目录权限 0700，私钥权限 0600。普通用户目标的导出也通过有权限的管理会话完成，不把私钥放到公共下载目录。

流程为：生成密钥对 → 通过现有连接下载私钥 → 在本地保存并设置访问权限 → 使用下载的这把私钥建立新连接 → 按需进入认证切换流程 → 提交成功后清理服务器临时私钥。

验证时必须使用新生成密钥对应的身份，不能用旧密钥登录成功来确认新密钥已经保存可用。第一次验证成功可以进入切换阶段，但服务器临时私钥保留到整个操作提交后再清理。

取消、超时或失败时，按本次操作的恢复点撤销尚未提交的公钥变更，并清理临时导出文件；菜单显示待下载状态和剩余时间，允许明确延期。清理操作只删除工具生成的指定文件，不接触已有密钥，也不宣称能在 VPS 的底层存储上实现可靠的安全擦除。

## 切换流程

默认仅为选定用户关闭密码和键盘交互认证，保留其他用户的策略。root 已具备可用密钥时，可以直接进入验证流程。

| 阶段 | 工具行为 | 进入下一阶段的条件 |
| --- | --- | --- |
| 检查 | 检测用户、现有认证、配置冲突和 SSH 服务 | 原配置可通过校验，环境在支持范围内 |
| 备份 | 保存修改对象、权限、属主、校验值与恢复信息 | 备份落盘并重新读取验证成功 |
| 准备公钥 | 启用必要的公钥认证、追加选定公钥，保留原认证方式 | 配置校验成功，独立回退任务已登记 |
| 第一次验证 | 从本地创建新连接，使用指定私钥登录 | 新公钥可以登录；不是复用旧连接 |
| 应用策略 | 写入目标用户的认证策略，校验并重载 SSH | 解析结果符合目标，重载成功 |
| 第二次验证 | 在新策略下再次创建新连接 | 确认仍能通过公钥登录 |
| 提交 | 记录结果，取消回退任务，保留备份 | 状态写入成功，提交与回退没有竞态 |

每个待确认的修改阶段默认给 5 分钟。需要延长时提供明确的延期操作。超时、配置校验失败或重载失败时恢复本次修改前的配置；原来禁止 root 密码登录的机器，恢复后也保持这一原始限制。

“恢复”与“开启密码登录”不同。第一版优先提供准确恢复，不用 `PasswordAuthentication yes` 代替回退。

## 新连接如何验证

服务器菜单提供一条适合当前端口和目标用户的本地测试命令。你的连接可以使用现有 `taipei101-lax1` 别名和保存的 SSH 配置，无需重新录入私钥。

OpenSSH 验证必须强制公钥认证、禁止密码和键盘交互回退，并禁用连接复用。仅设置 `ControlMaster=no` 还不够；还应使用 `ControlPath=none` 或 `-S none`。

新的验证会话需要在当前阶段开始后建立，并使用一次性操作编号确认。原会话不能直接点“完成”来代替新连接测试。终端关闭或中途退出也不能自动提交。

第一版采用用户从新会话运行确认命令的方式，并通过 `ExposeAuthInfo` 提供的 `SSH_USER_AUTH` 文件核验该连接的实际公钥指纹。缺少认证凭据时拒绝确认，不依赖不完整的认证日志或仅凭用户点击完成。

后续本地辅助程序可以按保存的 SSH 配置自动发起两次强制公钥新连接并提交确认。辅助程序应正常校验已信任的服务器主机指纹，并支持已有的跳板连接。私钥留在本地，使用 ssh-agent 或交互输入私钥口令。

FinalShell 用户可以建立独立连接、明确选用私钥认证，并从新会话执行确认命令。已有窗口仍然在线不能作为新策略可登录的证据。

依据：[SSH 连接复用](https://man.openbsd.org/ssh_config#ControlPath)。

## 配置写入和回退

### 保留现有配置

保留 cloud-init、SSH 配置片段及其他工具的设置。OpenSSH 通常使用首先获得的选项值；不能假定命名为 `99-*.conf` 就能覆盖之前的设置。

全局配置片段只放全局设置。目标用户的 `Match` 策略使用明确标记的独立配置块，初版优先考虑在主配置末尾追加。已有更早匹配规则会影响它时，停止并展示冲突，不能报告切换成功。

不要把含有 `Match` 的片段随意放到主文件顶部的通配 `Include` 中，也不能假定 `Match all` 恢复了全局作用域。每种写入方案均先验证完整配置语法，再针对目标用户回读有效结果。需要比较对未选定用户的影响。

安装、升级和普通状态查看只部署或读取程序。认证修改发生在用户选择相应操作后。

### 独立回退任务

回退任务使用磁盘上的 systemd service/timer，不依赖菜单进程、SSH 会话或后台 `sleep`。绝对截止时间配合日历定时器和 `Persistent=true`，并登记未完成操作，使重启后可以处理错过的回退。

修改认证策略前验证回退任务已成功启动。无法建立独立回退机制时，拒绝自动关闭密码。

提交和定时回退使用同一把操作锁，处理前核对操作编号与阶段，防止已经确认的操作被迟到的回退任务撤销。回退执行后校验配置、重载 SSH，并记录是否真正成功。

自动回退恢复本次修改前的状态，不保证修复原本存在的问题或服务器以外的网络故障。

依据：[systemd 定时器的持久化语义](https://github.com/systemd/systemd/blob/main/man/systemd.timer.xml)。

### 备份和其他工具配合

状态和备份放在 `/var/lib/sshkeytool/`，目录权限 0700，文件权限 0600。记录操作编号、目标用户、修改对象、前后校验值、截止时间和验证记录。

恢复尽量只撤销本工具的配置块与密钥变更。发现修改对象被其他程序改动时，不用整份旧配置覆盖新内容；保留备份并报告需要合并的对象。无法完成安全恢复时明确显示“回退失败”，不输出成功提示。

与现有 SSH 端口工具约定共用的 SSH 配置操作锁，并在修改前重新检查配置。第一版不修改 SSH 端口、防火墙和 Fail2ban；端口修改或备份恢复后，重新检测并提示需要新的连接验证。

## 拟议实现与工具箱接入

沿用现有工具箱的 Python 3.8+ 环境，核心使用 Python 标准库，并调用系统 OpenSSH/systemd 命令。安装器采用 Bash。

建议新增独立目录：

```text
ssh-key/
  ssh_key_tool.py
  install.sh
  README.md
  tests/
```

独立命令安装为 `/usr/local/sbin/sshkeytool`。统一入口新增 `vpstools run sshkey ...`，主菜单新增“SSH 密钥登录管理”，安装/更新项继续放在功能菜单末尾。

拟议接口：

```text
sshkeytool                         中文菜单
sshkeytool status --user root      查看指定用户状态
sshkeytool keys list --user root   查看公钥指纹列表
sshkeytool keys add --user root    进入导入流程
sshkeytool keys generate --user root 生成新密钥对并进入下载验证流程
sshkeytool switch --user root      进入两阶段验证流程
sshkeytool confirm <操作编号>      从新连接确认当前阶段
sshkeytool rollback <操作编号>     恢复本次修改前的状态
sshkeytool history                 查看操作与回退记录
```

这些接口已实现；`keys add` 命令需提供 `--file`、`--key`、`--github` 或 `--url` 并交互确认。菜单支持直接选择来源，新增第 9 项用于新连接确认和延期。不能用一个 `--yes` 参数跳过新连接验证。

## 第一版验收

| 场景 | 应有结果 |
| --- | --- |
| `taipei101-lax1` 的注释配置和现有密钥 | 正确显示允许公钥、root 禁止密码，保留现有密钥 |
| 开启项省略、带缩进、位于 Include 文件 | 按 OpenSSH 解析结果展示，不误报未设置 |
| 全局允许密码，root 单独禁止密码 | 分别展示全局与目标用户结果 |
| 导入重复公钥，或已有同指纹限制记录 | 不重复添加，不解除已有密钥限制 |
| 自动生成密钥、下载后验证 | 公私钥匹配，不覆盖原密钥，新连接使用新私钥 |
| 私钥未下载、取消或操作超时 | 不关闭原登录方式，撤销未提交变更并清理临时私钥 |
| 私钥导出与操作记录 | 不默认打印私钥，备份和日志不包含私钥或口令 |
| 普通用户及自定义授权文件 | 正确选择属主和有效路径，不能写到 root 家目录 |
| 复杂 Match 或多因素认证 | 展示适用条件与冲突，不盲目覆盖 |
| 私钥口令、跳板连接、自定义端口 | 新连接验证支持现有本地连接方式 |
| 旧 SSH 连接可用但新连接失败 | 不提交，保留或触发回退 |
| 用户不确认、关闭终端、重载失败 | 独立任务恢复本次修改前的配置 |
| 服务器重启、确认与回退同时触发 | 未完成操作被正确处理，已提交操作不再回退 |
| 其他工具在期间修改配置 | 不整份覆盖外部改动，清楚报告合并或回退失败 |

解析、写入和回退测试先在临时目录使用真实 OpenSSH 完成，再在用户指定的 `stone-hk` 上执行安装、新连接、认证修改和真实 systemd 定时回退测试。其他 VPS 不做安装或修改测试；测试后恢复 `stone-hk` 原认证配置和原公钥。

## 版本顺序

第一版完成准确状态识别、已有公钥管理、VPS 自动生成密钥对和下载验证、指定用户切换、两次新连接确认、独立回退，以及 `vpstools` 接入。

第二版增加读取你现有 SSH 别名的本地辅助程序，自动执行验证和确认；之后再加入逐台执行、逐台出结果的多 VPS 管理。
